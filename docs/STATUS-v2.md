# v2 고도화: 현재 구현 상태와 계획 (2026-10-15, 기준 커밋 414c8ad)

코드와 문서를 직접 확인해 분류했다. 각 항목은 ✅ 완료(재사용), 🟡 부분 구현, ❌ 미구현으로 표시한다.

## 1. 어댑터·플러그인 구조

| 항목 | 상태 | 근거 |
|---|---|---|
| 드라이버 계약(Driver/Session, Manifest, Capabilities, typed Value, 다형 ResultSet) | ✅ | `crates/dbcore`, ARCHITECTURE.md |
| 등록 한 줄로 DB 추가, UI는 수정하지 않음 | ✅ | SQLite 커밋 `3e09c82`(ui/dbcore 변경 0), PLUGIN_GUIDE, KV 예제 |
| 관계형 이외의 패러다임(문서/키-값)을 실제 DB로 검증 | ❌ | KV는 미등록 예제뿐이고, 문서 DB 드라이버는 없음 |
| 외부 프로세스 플러그인(JSON-RPC) | ❌(의도적 제외) | ADR-0001. 계약이 serde 직렬화 가능하므로 경계 이동은 가능 |

**다음 DB는 MongoDB로 정한다.**
- SQLite와 MySQL은 PG와 같은 관계형이다. 새로 검증되는 것이 거의 없다.
- MongoDB는 아직 검증하지 않은 경로를 실제로 시험한다: 문서 패러다임, 컬렉션 탐색, 비SQL 명령 언어, 문서·JSON 결과 뷰, ObjectId·Decimal128·Date·BinData 같은 고유 타입, 스키마 없는 데이터의 필드 추론.
- 요구사항이 명시한 "문서 DB: 컬렉션 탐색, 문서·JSON 결과"를 직접 충족한다.
- Redis(키-값)는 그다음 후보다. KV 예제 crate가 이미 계약을 확인했으므로, 실제 서버로 검증할 때의 위험이 상대적으로 작다.

## 2. 데이터 뷰어와 연결된 탐색

| 뷰어/흐름 | 상태 | 근거 |
|---|---|---|
| 테이블(가상화, 정렬/필터, 타입 헤더) | ✅ | VirtualTable, W4 |
| 그래프(Canvas, Worker 레이아웃, 확장, 검색, LOD) | ✅ | GraphView, W4/W4b |
| 같은 결과 안에서 Graph↔Table↔JSON 전환 | ✅ | Results.tsx |
| JSON(문서) 뷰 | 🟡 | `<pre>`만 나열한다. 트리, 접기, 가상화, 필드 경로 탐색이 없음 |
| ERD(관계형 스키마 다이어그램) | ❌ | 없음 |
| 뷰어 간 연결 탐색 | ❌ | FK 셀 → 참조 행, ERD 테이블 → 컬럼/조회, 그래프 노드 → 같은 라벨의 표, 표 행 → 문서 상세 같은 이동이 없음 |
| 행 상세/값 인스펙터 | 🟡 | 셀 상세 패널만 있음 |

## 5. 권한을 적용한 MCP 접속

🟡 부분 구현. localhost 브리지, bearer 토큰, Origin 거부는 있다. 그러나 토큰이 하나이고 권한이 전부 아니면 전무다. 클라이언트별 범위 토큰, 연결 허용 목록, 감사 로그가 없다.

## 6. 스키마와 작업 맥락을 이해하는 AI 지원

❌ 미구현(v1 제약에 따라 의도적으로 제외했다).

- 환경 사실: 이 머신에는 LLM 공급자 API 키가 없다.
- 설계 방향:
  - (a) MCP로 스키마 요약과 작업 맥락(활성 탭, 최근 오류, 선택한 행)을 제공한다. 외부 에이전트(Claude 등)가 앱 맥락을 이해하고 SQL/Cypher를 제안한다. 생성된 쿼리는 4·5의 권한과 3의 미리보기를 거친다.
  - (b) 앱 안의 "AI 도움" 패널. BYO 공급자이고 키는 키체인에 둔다. 기본은 꺼짐이며 행 데이터는 전송하지 않는 것이 기본값이다.
- 실제 검증: (a)는 코디네이터(Claude)가 MCP 클라이언트로 실행한다. (b)는 mock 공급자로 검증하고, 실제 공급자 호출은 키가 없으므로 미검증으로 표시한다.
