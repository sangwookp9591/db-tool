# ADR-0004: AX 네이티브 워크벤치 (0.3.0)

- 상태: 채택 (2026-10-19)
- 결정자: 사용자(요구), 코디네이터(설계)
- 관련: ADR-0002(에이전트 인터페이스), ADR-0003(설치형 드라이버)

## 배경

사용자 요구:
- "SQL 편집기(리팩터링·쿼리 분석·실행 계획 시각화), 관리 기능(사용자·권한·백업·복원·마이그레이션·스키마 비교·가져오기), 연결 방식(SSH 터널·클라우드 IAM·프록시)을 UX/UI적으로 편리하게 만들고 싶다."
- "Ax, AI 시대에 맞는 느낌으로 만들어 줘. 기능들도."
- "Claude OAuth, GPT OAuth 같은 기능도 넣자. MCP 연결도 있지만 로그인 연결해서도 사용할 수 있게."

## 결정: 세 가지 원칙

### 원칙 1. 모든 기능은 "의도 → 제안 → 미리보기 → 승인 → 실행"을 따른다

AI 시대의 DB 도구에서는 사람이 문법을 외워 직접 입력하는 대신, **의도를 말하면 AI가 구체안을 만들고, 사람은 결과를 검토해 승인한다.** AxDB는 이미 제안(AI가 새 탭에 쿼리를 넣음), 미리보기(실행 후 롤백), 승인(write-with-approval)을 갖고 있다. 0.3.0의 모든 신규 기능은 이 파이프라인 위에 올린다.

| 단계 | 사람이 직접 할 때 | AI가 할 때 |
|---|---|---|
| 의도 | 폼, 체크박스, 드래그 | 자연어 입력창(⌘K 또는 기능 화면의 "AI에게 맡기기") |
| 제안 | 화면이 SQL이나 작업 계획을 생성 | AI가 같은 형식의 계획을 생성하고 **근거**를 붙임 |
| 미리보기 | 기존 preview 엔진(쓰기는 실행 후 롤백, 읽기는 비용 추정) | 같음 |
| 승인 | 버튼 클릭(파괴적 작업은 확인 문구 입력) | 같음. 에이전트는 권한 등급에 따라 승인 요청 |
| 실행 | 진행률, 취소, 감사 로그 | 같음 |

**AI는 직접 실행하지 않는다.** AI 출력은 항상 "계획" 객체이고, 실행은 사람이 승인한 경우나 권한 정책이 허용한 경우에만 같은 파이프라인으로 한다. 이 불변식은 코드 리뷰와 테스트로 강제한다.

### 원칙 2. 화면, 에이전트, AI가 같은 "작업(Operation)"을 공유한다

신규 기능은 모두 `Operation`으로 정의한다. 같은 Operation을 다음 세 경로가 쓴다.
1. **UI**(사람)
2. **MCP 도구**(외부 에이전트: Claude Code, Codex 등). 권한 등급 none/read/preview/write-with-approval을 그대로 적용한다.
3. **내장 AI 어시스턴트**(앱 안 로그인)

```
Operation { id, kind, connection, params, plan?, risk, needs_approval }
  kind: explain | analyze | refactor | import | schema_diff | migrate | backup | restore | grant | connect_test ...
  plan: 미리보기 산출물(SQL 목록, 비용, 영향 행 수, diff, 위험 경고)
  risk: read | write | destructive  → 권한·승인 정책을 결정
```

- read Operation(explain, analyze, diff 계산)은 read 권한으로 실행된다.
- write Operation(import, migrate, grant)은 preview 권한으로 계획까지 만들 수 있고, 적용에는 write-with-approval과 사람 승인이 필요하다.
- destructive Operation(restore 덮어쓰기, DROP이 포함된 migrate)은 사람만 승인할 수 있고, 확인 문구를 입력해야 한다. 에이전트는 요청만 할 수 있다.

### 원칙 3. 드라이버가 선언한 능력만 보여 준다

`Capabilities`에 능력 플래그를 추가하고(아래 표), UI·MCP·AI는 이 플래그로만 분기한다. driver-id로 분기하지 않는다는 기존 불변식을 유지한다. 프로토콜은 `protocol: 1` 안에서 **선택 메서드로 확장**한다. 모르는 메서드는 `unsupported`로 응답하므로 구버전 드라이버도 호환된다.

| 능력 | 메서드 | PG | Neo4j | SQLite | Mongo | Redis |
|---|---|---|---|---|---|---|
| `explain` | `explain(query, analyze: bool)` → 정규화 PlanTree | EXPLAIN (FORMAT JSON[, ANALYZE]) | EXPLAIN/PROFILE | EXPLAIN QUERY PLAN | explain() | - |
| `lint` | 호스트 공통(SQL/Cypher 정적 규칙) + 드라이버 통계 | ✓ | ✓ | ✓ | 부분 | - |
| `import_rows` | 미리보기·적용은 기존 edits 경로를 재사용(대량 배치) | COPY | UNWIND 배치 | 트랜잭션 INSERT | insertMany | 파이프라인 |
| `schema_snapshot` | 정규화 스키마(테이블·컬럼·인덱스·제약·뷰). diff는 호스트가 계산 | ✓ | 라벨·관계·제약·인덱스 | ✓ | 컬렉션·인덱스·검증 | - |
| `ddl_render` | diff → DDL 생성 | ✓ | 제약·인덱스 Cypher | ✓ | createIndex 등 | - |
| `roles` | 역할·권한 조회, grant/revoke 계획 | ✓ | Enterprise만(감지 후 비활성) | - | ✓ | ACL |
| `backup` | 논리 백업 스트림(드라이버 내장 구현. 외부 바이너리 의존 없음) | 스키마+COPY 스트림 | Cypher 덤프 | `.backup` API | 컬렉션 NDJSON | - |

## 기능 설계

### A. 연결 (0.3.0 최우선)

- **스마트 붙여넣기:** 연결 문자열, JDBC URL, `psql` 명령, `~/.ssh/config`의 Host, AWS RDS 엔드포인트를 붙여 넣으면 칸을 자동으로 채운다. 파싱은 호스트에서 결정적으로 하고 AI는 쓰지 않는다. 비밀번호가 들어 있으면 키체인으로 옮기고 입력창에서 지운다.
- **네트워크 계층(호스트 공통, 드라이버와 무관):** 드라이버에는 항상 `127.0.0.1:<로컬 포트>`만 넘긴다. 따라서 모든 드라이버가 자동으로 SSH와 프록시를 지원한다.
  - SSH: `russh`로 구현하고 시스템 ssh에 의존하지 않는다. 키 파일, ssh-agent, 비밀번호, 점프 호스트(ProxyJump 1단계 이상)를 지원한다. 처음 접속할 때 **호스트 지문 확인**을 하고 known_hosts는 앱 데이터에 둔다. 연결이 끊기면 지수 백오프로 재연결하고 상태바에 표시한다.
  - 프록시: SOCKS5와 HTTP CONNECT
- **클라우드 IAM**
  - AWS RDS·Aurora(PG): `~/.aws` 프로필이나 SSO를 고르면 SigV4로 15분짜리 인증 토큰을 발급하고, 만료 전에 자동으로 갱신해 비밀번호 자리에 넣는다. aws-sdk 전체 대신 서명만 직접 구현하거나 경량 crate를 쓴다.
  - GCP Cloud SQL: gcloud ADC 토큰으로 IAM 사용자 인증
  - 둘 다 "IAM" 탭에서 프로필을 고르는 드롭다운 하나로 끝나야 한다.
- **단계별 연결 테스트:** `DNS → SSH 인증 → 터널 → TLS → DB 인증 → 권한 확인` 순서로 각 단계에 ✓, ✗, 소요 시간을 표시한다. 실패하면 원인별 해결 안내를 보여 주고(예: 지문 불일치, 키 권한 0644, IAM 토큰 거부, pg_hba), 로그인되어 있으면 **"AI로 진단"** 버튼을 둔다(redaction을 적용한 단계 로그만 보낸다).
- **보안:** 키 암호, SSH 비밀번호, 프록시 비밀번호는 OS 키체인에 저장하고 로그에서는 redaction한다. 지문이 바뀌면 연결을 차단하고 경고한다.

### B. 편집기

- **실행 계획(Plan 탭):** 결과 옆에 '계획' 탭을 둔다. 정규화된 PlanTree를 노드 트리와 가로 비용 막대로 보여 주고, 가장 비싼 경로를 강조한다. 예상 행 수와 실제 행 수가 10배 이상 차이 나면 경고한다. 노드를 클릭하면 관련 테이블과 인덱스 탐색기로 이동한다. ANALYZE는 쓰기 쿼리를 실제로 실행하므로 미리보기와 같은 롤백 경로에서만 허용한다.
- **AI 계획 해설:** "왜 느린가"를 세 문장으로 설명하고, 인덱스 추천 DDL을 **제안**한다(새 탭이나 미리보기로 넘김. 실행하지 않음).
- **분석(린트):** 입력 중 300ms 디바운스로 결정적 규칙을 검사한다. WHERE 없는 UPDATE/DELETE, 큰 테이블(통계 기준) 전체 스캔, 카티션 곱, `SELECT *` 대량, Cypher의 무제한 가변 길이 패턴 등이다. 편집기에 밑줄과 빠른 수정(quick fix)을 표시한다. 실행 직전에는 위험 등급 배지를 보여 준다.
- **리팩터링:** 호스트의 SQL 파서(sqlparser-rs)로 결정적으로 처리한다. 서식 정리, `SELECT *`를 컬럼 목록으로 펼치기, 별칭 이름 바꾸기, 하위 쿼리를 CTE로 추출하기다. **자연어 리팩터링**("이 쿼리를 페이지네이션 가능하게", "N+1 없애 줘")은 AI가 diff로 제안하고 사람이 수락한다.

### C. 관리

- **가져오기:** 파일을 표나 탐색기에 끌어다 놓는다 → 형식 감지(CSV/TSV/JSON/NDJSON/XLSX) → **컬럼 매핑**(이름과 타입 자동 추론, AI 매핑 제안은 낮은 확신일 때만) → 새 테이블 또는 기존 테이블 선택 → 미리보기(처음 100행, 변환 오류 행, 제약 위반 예상) → 적용(한 트랜잭션, 진행률, 취소)
- **스키마 비교:** 연결 A·B(또는 스냅숏 파일)를 고른다 → 정규화 스냅숏 diff를 추가·삭제·변경 트리로 보여 준다 → 마이그레이션 DDL을 생성하고 위험 표시(DROP, 타입 축소 = destructive)를 한다 → 미리보기 → 승인. AI는 변경 요약과 위험 해설, 롤백 DDL 초안을 제공한다.
- **마이그레이션:** 폴더(Flyway/Prisma/Rails/plain `NNN_*.sql`)를 연결하면 적용된 것과 대기 중인 것을 타임라인으로 보여 준다. 대기 중인 것은 미리보기 후 적용한다. "현재 diff로 다음 마이그레이션 파일 만들기"(AI가 이름을 짓고 주석을 단다)를 지원한다.
- **백업·복원:** 드라이버 내장 논리 백업을 쓰고, 출력은 `.axbackup`(zstd, manifest, 체크섬)이다. 진행률과 취소를 지원한다. 복원은 **새 DB나 빈 대상**을 기본으로 하고, 기존 대상 덮어쓰기는 destructive로 분류해 연결 이름을 직접 입력해야 진행된다.
- **사용자·권한:** 역할과 객체를 축으로 한 권한 행렬을 보여 준다. 셀을 토글하면 GRANT/REVOKE 계획이 쌓이고, 미리보기 후 적용한다. 자연어 입력 예: "analyst 역할에 public 스키마 읽기 전용" → AI가 계획을 만든다. "이 사용자가 실제로 할 수 있는 것"을 문장으로 설명한다.

### D. AI 연결: 로그인과 MCP 두 경로

| 경로 | 설명 |
|---|---|
| **앱 안 로그인(신규 확장)** | 공급자를 추상화한다. **Anthropic**: 기존 Claude OAuth를 유지하고 API 키를 지원한다. **OpenAI**: "ChatGPT로 로그인"(OAuth PKCE, 루프백 리디렉션)과 API 키를 지원한다. 토큰은 OS 키체인에 저장하고 자동 갱신한다. 설정에서 공급자, 모델, 사용량(토큰)을 고른다. 로그인하지 않았으면 AI 버튼은 '로그인 필요' 상태로 보이고 기능은 숨기지 않는다. |
| **MCP(유지·확장)** | 외부 에이전트가 같은 Operation을 도구로 호출한다. 신규 도구: `explain_query`, `lint_query`, `schema_diff`, `plan_import`, `plan_migration`, `plan_grants`, `backup_status`. 계획 생성은 preview 권한, 적용 요청은 write-with-approval이며 앱에서 사람이 승인한다. |

- 공급자 인터페이스: `AiProvider { login, refresh, complete(messages, tools, stream) }`. 기존 assistant.rs를 이 인터페이스로 일반화한다.
- 컨텍스트 원칙(기존 유지): 스키마와 통계 요약만 보낸다. **행 데이터와 비밀은 보내지 않는다.** 결과 샘플을 보내려면 사용자가 명시적으로 토글해야 한다.
- OpenAI OAuth의 클라이언트 등록이나 정책상 서드파티 앱의 ChatGPT 로그인이 허용되지 않으면, 공식으로 허용된 방식(API 키, 또는 허용된 OAuth 흐름)으로 대체한다. 이 결정은 구현자가 공식 문서를 확인한 뒤 보고한다. **비공식 토큰 추출이나 우회는 하지 않는다.**

## UX 언어 (AX 느낌)

- **명령 우선:** ⌘K 하나로 모든 Operation을 부른다. 자연어를 입력하면 AI가 Operation 후보를 제시하고, 정확한 명령어를 입력하면 바로 실행한다.
- **계획 카드:** 모든 제안은 같은 카드 컴포넌트로 보여 준다. 카드에는 제목, 근거, 영향(행·객체 수), 위험 배지, 미리보기와 적용 버튼이 있다. 기존 ToolCall과 CallChip 디자인 언어를 재사용해 '에이전트가 일하는 화면'이라는 일관성을 준다.
- **근거 표시:** AI 출력에는 항상 어떤 스키마와 통계를 근거로 했는지 칩을 붙인다.
- **조용한 모션:** 상태 전환에만 모션을 쓰고, 유휴 상태 애니메이션은 0이다. reduced-motion을 따른다.

## 단계와 배치

| 단계 | 내용 | 배치 |
|---|---|---|
| W1 | 연결: 네트워크 계층(SSH, 프록시), IAM, 스마트 붙여넣기, 단계별 테스트 | Codex Sol/high |
| W2 | 편집기: explain 능력·PlanTree, 린트, 결정적 리팩터링 | Codex Sol/medium |
| W3 | 관리 1: 가져오기, 스키마 스냅숏·diff·DDL, 마이그레이션 폴더 | Codex Sol/medium |
| W4 | 관리 2: 백업·복원(.axbackup), 역할·권한 | Codex Sol/medium (W3 이후) |
| W5 | AI 공급자 추상화: Anthropic·OpenAI 로그인, 자연어 → Operation, MCP 신규 도구 | Codex Sol/high |
| W6 | UI 전체: 연결 폼 단계형, 계획 탭, 린트 표시, 가져오기 마법사, diff 트리, 권한 행렬, 계획 카드, ⌘K | Codex Astra/high (mock 계약으로 병행 시작) |
| V | 독립 검증(실DB, SSH 컨테이너, 보안, 실제 앱 화면) | Opus |

테스트 인프라: SSH 서버 컨테이너(`linuxserver/openssh-server`, 비밀번호와 키 모두 사용)를 PG 테스트 컨테이너 앞에 둔다. SOCKS 프록시 컨테이너, PG 역할 픽스처를 둔다. 사용자 DB와 사용자 SSH 호스트에는 접속하지 않는다. IAM은 실제 AWS 계정이 없으면 SigV4 서명을 공식 테스트 벡터로 검증하고 실연결은 '미검증'으로 보고한다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| AI가 직접 실행(자율 에이전트 모드) | 원칙 "사용자 데이터에 자동 쓰기 금지"와 충돌한다. 승인을 단계로 남긴다 |
| 시스템 `ssh -L`과 `pg_dump` 같은 외부 바이너리 호출 | 사용자 환경에 따라 동작이 달라지고, 배포와 Windows 호환성이 나빠진다 |
| 드라이버별 SSH 구현 | 같은 코드를 중복하게 되고, 새 드라이버가 자동으로 지원받지 못한다 |
