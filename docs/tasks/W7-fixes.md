# W7-fixes: 코디네이터 실제 앱 검증에서 발견한 결함 수정

이 작업은 반드시 끝까지 완료한다. 합리적인 가정으로 계속 진행하고, 결정한 내용은 마지막 보고에 적는다. 사용자 지시가 skill 지침보다 우선한다.

## 배경
- 코디네이터가 실제 debug 앱을 MCP 브리지로 구동해 E2E를 실행했고, 테스트 PG와 Neo4j 대상으로 21/21 통과했다(`bench/e2e-bridge.mjs`).
- 이어서 화면을 직접 확인하다가 아래 결함을 발견했다.

## 수정할 결함 (각각 회귀 테스트 포함)

1. **[정확성] Neo4j 결과 컬럼 순서가 RETURN 순서가 아니다.**
   - 원인: `crates/driver-neo4j/src/lib.rs`의 `keys.sort()`
   - 고칠 내용: Bolt RUN 응답 SUCCESS의 `fields` 순서를 그대로 쓴다. neo4rs가 이 값을 노출하지 않으면 Row의 실제 필드 순서를 쓰고, 그 순서가 보장되는지 neo4rs 소스로 확인한다.
   - **결과가 0행이어도 컬럼 헤더가 있어야 한다.**
   - 테스트: `RETURN 1 AS z, 2 AS a, 3 AS m` → 컬럼이 [z, a, m]. `MATCH (n:NoSuchLabel) RETURN n.x AS x, n.y AS y` → 0행, 컬럼 [x, y].
2. **[UI] 결과 영역이 너무 작다.**
   - 에디터와 결과 사이에 드래그 가능한 분할선을 둔다. 비율은 탭별로 저장하고, 결과 영역 최소 높이는 240px로 한다.
   - 그래프 첫 렌더와 "Reset view"는 **fit-to-view**로 동작한다. 모든 노드가 여백을 두고 보이도록 줌과 이동을 맞춘다.
3. **[UI] 관계 라벨이 겹친다.**
   - 같은 두 노드 사이의 다중 관계나 반대 방향 관계는 곡선 오프셋으로 분리한다.
   - 줌 수준이 낮으면 라벨을 생략한다(LOD). W4의 LOD와 통합한다.
4. **[성능] UI에서 실행한 Neo4j 쿼리가 4행에 1,145ms 걸렸다.**
   - 같은 종류의 쿼리를 에이전트 경로로 실행하면 17~56ms다. UI 실행 경로에서 원인을 계측해 찾고 고친다. 후보: execute_stream 청크 처리, 탭별 세션, 그래프 레이아웃 시간이 elapsed에 포함되는지 여부.
   - 고친 뒤 같은 쿼리를 UI 경로로 실행했을 때 100ms 미만인지 측정해 보고한다.
5. **[에이전트] 앱 시작 직후 `list_drivers`가 빈 배열을 돌려줄 수 있다.**
   - 도구 레지스트리는 manifest 로드가 끝날 때까지 기다린 뒤 응답하거나, 준비가 끝난 뒤에 등록되어야 한다.
6. **[보안/UX] 연결 폼을 취소한 뒤 다시 열면 이전 입력(비밀번호 포함)이 남아 있다.**
   - 폼을 닫거나 취소하거나 저장하면 draft를 초기화하고, secret 입력값은 메모리에서 지운다.
7. **[UX] Path 요약이 `(0)-[:ACTED_IN]->(3)`처럼 내부 인덱스로 표시된다.**
   - 노드 캡션(name/title/첫 문자열 속성), 없으면 첫 라벨로 `(Alice)-[:ACTED_IN]->(Matrix)`처럼 표시한다.
8. **[보안] 로그 파일 권한이 0644다.** 0600으로 만든다(Unix).

## Constraints
- UI에서 드라이버 id로 분기하지 않는다. grep 결과 0건을 유지한다.
- 테스트 DB만 쓴다: PG 55432 / Neo4j 57687.
- git commit을 하지 않는다.
