# W1 연결 구현 보고서

2026-10-19. [ADR-0004 A절](adr/0004-ax-native-workbench.md), [ADR-0003](adr/0003-installable-drivers.md), [아키텍처](ARCHITECTURE.md)를 기준으로 이전 W1의 `src-tauri/src/net/`과 테스트 픽스처를 이어 완성했다. 시작부터 다른 워커의 변경이 있던 공유 작업 트리에서 W1 소유 변경만 추가했고 commit/push, 사용자 앱·GUI·DB·SSH 호스트 접근은 하지 않았다. `target-w1`만 사용했으며 `dist/`, `target/`, `target-rel/`은 건드리지 않았다.

SSH는 russh로 키·암호화된 키·agent·비밀번호와 최대 8개 점프 호스트를 지원한다. 앱 데이터의 known_hosts에 확인한 키를 원자적으로 저장하고, 미등록 키는 확인 요청 뒤에만 신뢰한다. 키 변경은 차단하며 재연결 중에도 `disconnected`와 원인 코드를 보낸다. 재시도 간격은 1/2/4/8/16초이며 DB 작업은 재실행하지 않는다. SOCKS5 사용자 인증과 HTTP CONNECT Basic 인증을 포함한 호스트 공통 루프백 릴레이를 구현했다. PG 인증서 검증과 취소 소켓은 원래 서버 이름을 유지하고, Mongo/Neo4j의 즉시 TLS는 호스트에서 원격 이름으로 검증한다. Mongo는 로컬 릴레이를 우회하지 않도록 directConnection을 사용하되 지정한 replicaSet 이름은 보존한다.

기존 프로필에는 network 없음과 password 인증을 기본 적용한다. SSH·점프·프록시 비밀은 기존 OS 키체인 경로를 사용하고 프로필 타입은 비밀 필드를 거부한다. 스마트 붙여넣기는 URL/JDBC, psql, libpq 키워드, SSH Host 블록, RDS 주소를 결정적으로 해석한다. 붙여넣은 비밀번호는 키체인으로 옮기고 반환 객체·정제 입력에는 넣지 않는다. 포트 0·잘못된 포트·psql의 다른 DB URL을 거부하는 회귀도 추가했다. AWS는 shared credentials/config와 SSO 캐시를 읽어 SigV4 토큰을 만들고, 리전은 명시값 → 선택 프로필 → RDS 주소 순으로 찾는다. 새 연결 시 남은 토큰 수명이 120초 이하면 갱신한다. GCP는 ADC authorized_user와 service_account 토큰을 사용한다. IAM은 verify-full TLS를 강제한다.

커맨드는 `connection_parse`, `connection_credentials_save`, `connection_host_key_confirm`, `connection_test_steps`, `iam_profiles`다. 테스트 Channel은 dns/ssh/tunnel/tls/db_auth/permissions 단계와 상태·소요 시간·원인 코드·해결 안내 키를 보낸다. TLS와 SSH 오류를 DB 인증 실패로 중복 표시하지 않도록 수정했다. 전역 `connection-network`는 host_key/network 이벤트를 보내며 network의 선택적 code를 W6에 알렸다. W6이 브라우저 mock, 선택형 IAM 리전, 지문 변경 role=alert를 같은 계약으로 연결한 소스를 확인했다. AI 실행 경로는 추가하지 않았다.

실DB 네트워크 검증은 기존 axdb-test-ssh(55222), axdb-test-socks(55080)를 이어 사용했다. SSH 키/암호화 키/agent/비밀번호/ProxyJump, SOCKS5, HTTP CONNECT, 프록시+SSH의 8개 조합 × PG·Mongo·Redis × 내장/플러그인 = **48개 실제 연결**에서 ping/server_info를 확인했다. 별도로 재연결, 저장 키와 실제 SSH 서버 키 불일치 차단 및 오류 이벤트, PG TLS 호스트 이름 불일치 거부, TLS 취소 후 세션 재사용을 실제 소켓으로 검증했다. 추가한 axdb-test-w1-pg-tls는 127.0.0.1:55433만 공개한다. macOS에서 테스트 인증서의 EKU 실패를 재현해 별도 CA와 serverAuth 서버 인증서로 수정했다. cold-start 셋업 스크립트를 처음부터 다시 실행하지는 않았으며 Python 구문 검사를 통과했다.

검증 명령은 `CARGO_TARGET_DIR=target-w1 cargo build --workspace --bins`, `AXDB_DRIVER_DIR=target-w1/debug`를 설정하는 `python3 scripts/test-network-run.py`, `CARGO_TARGET_DIR=target-w1 cargo clippy -p axdb -p driver-postgres --all-targets -- -D warnings`, `pnpm --dir ui exec tsc --noEmit`, `pnpm --dir ui test`다. 최종 결과는 아래 확인 기록을 따른다. AWS 서명은 [AWS 공식 SigV4 예제의 기대 서명](https://awsdocs.s3.amazonaws.com/S3/latest/s3-api.pdf)과 일치하는 테스트를 통과했다. [RDS IAM의 15분 수명](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.IAMDBAuth.Connecting.html), [Cloud SQL 수동 IAM 인증](https://docs.cloud.google.com/sql/docs/postgres/iam-logins)을 확인했다.

실제 AWS/SSO·GCP 계정 및 클라우드 DB 로그인, OS 키체인 왕복, 네이티브 GUI와 Windows는 미검증이다. 기본 AWS 자격 증명/SSO와 GCP 두 ADC 형식 이외의 assume-role/credential_process/외부 계정 federation은 구현 범위에 포함하지 않았다. Mongo SRV·다중 서버 발견은 단일 TCP 릴레이 경로에서 지원하지 않는다. 끊긴 DB 프로토콜 세션은 다시 열어야 하며 진행 중 쿼리를 자동 재생하지 않는다. 생성한 SSH 개인 키·무작위 비밀번호·IAM 토큰은 저장소와 보고서에 기록하지 않았다. 테스트 컨테이너와 target-w1은 코디네이터 확인을 위해 유지했다.

확인 기록: build --workspace --bins 통과. 마지막 실DB 실행에서 W1 네트워크 21개를 포함한 호스트 lib **111 PASS / 4 ignored**, 외부 플러그인 계약 **37 PASS**, updater **1 PASS**였고 성능 벤치 1개는 ignored다(`/tmp/axdb-w1-tests-complete.log`). tsc 통과, 최신 UI 전체 **122/122 PASS**다. 앞선 UI 실행의 온보딩 5초 timeout(119 PASS / 1 FAIL)은 숨기지 않고 기록한다. 최신 UI 계약·지문 경고 변경을 포함한 별도 전체 실행이 통과한 결과다. `git diff --check`와 Python 구문 검사도 통과했다.

전체 게이트 구분: W1 변경을 포함한 clippy는 한 차례 통과했다(`/tmp/axdb-w1-clippy-complete.log`). 이후 병행 W4 구현을 읽은 마지막 clippy는 `crates/driver-redis/src/administration.rs:19`의 comparison_to_empty로 실패했고 코디네이터에 전달했다(`/tmp/axdb-w1-clippy-final-snapshot.log`). 전체 cargo test도 위 런타임 테스트 뒤 rustdoc에서 진행 중인 W3/W4의 ProgressSink/import_rows_progress/backup_status 소스와 이미 빌드한 의존성 간 불일치로 종료 코드 1을 냈다. 앞선 apply_grants 불일치는 새 graph로 doc 검사를 재실행해 해결 확인했으나 새 공유 변경이 뒤따랐으므로 **최종 작업 트리 전체 cargo test/clippy 통과로 주장하지 않는다**. 병행 구현이 안정된 뒤의 전체 게이트는 코디네이터에게 남긴다.
