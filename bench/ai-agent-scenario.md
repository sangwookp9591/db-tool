# AI1 external agent verification (coordinator)

Run against an isolated AxDB config and the test databases only. This procedure makes no Anthropic request. Use a new client with explicit `get_schema_context`, `get_work_context`, `explain_error`, `list_connections`, `open_connection`, `open_query_tab`, `run_query`, and (when supported) `preview_changes` grants. Existing client allowlists intentionally do not grow automatically.

1. Start the candidate built with `CARGO_TARGET_DIR=target-ai1 CARGO_BUILD_JOBS=4`, `AXDB_CONFIG_DIR=<isolated test config>` and `AXDB_AGENT_BRIDGE=1`. Configure only PG `127.0.0.1:55432/axdb_test`, Neo4j `127.0.0.1:57687`, SQLite test file, or MongoDB `127.0.0.1:57017`. Supply credentials through the app; do not put tokens/keys in reports.
2. Read the private discovery file `<config>/agent-bridge.json` and connect an MCP client using `Authorization: Bearer <client token>`. Call `tools/list`, `list_connections`, then `open_connection({profile_id})`. Keep its `session_id`.
3. Call `get_schema_context({session_id, focus: "<existing entity>"})`. Verify `query_language` matches the manifest (SQL/Cypher/Mongo command JSON), entities and relationships appear, `schema_byte_limit` is 6000, and `selected_rows` is null. `schema_truncated` explicitly marks omitted metadata. Explorer-only drivers return their available metadata, not invented PK/FK.
4. Generate a read query from this context, then call `open_query_tab({session_id,text})`. Verify the editor changes and no database execution occurs. Call `get_work_context({})`: the active editor and connection must match; columns/row counts/errors appear only for retained runs.
5. Explicitly call `run_query({session_id,text,read_only:true})`. Validate a small bounded result against the test fixture. Save its `run` identifier. Make a deliberately invalid read query; pass the returned `run` to `explain_error({run})` and check the error kind/message and schema. Run metadata is bounded to the latest 20 executions and disappears on disconnect/restart.
6. For a preview-capable connection granted `preview`, use an idempotent fixture update with `preview_changes({session_id,text})`. Verify `committed:false`; re-read the fixture and confirm unchanged values. A `read` client must be denied preview. A write-with-approval request still requires the existing visible app approval; reject it once and verify no write.
7. Set this connection's client permission to `none`. Verify each of the three context calls returns no context, and when all grants are none those three tools disappear from `tools/list`. Revoke/expire the token and verify authentication fails. Revoke a grant during schema collection to verify the final authorization check.
8. For the optional assistant, without a key verify settings guidance, default off and no outbound request. With an explicitly authorized key (not provided in this run), enable it and ask a question: inspect live streaming, refusal UI, and schema cache usage. The generated query opens a new tab without executing; its Run is read-only. Writes require Preview then the separate approval button within the host's 60-second matching-preview lifetime.

Record native/MCP outcomes separately from mocked browser and HTTP checks. Do not claim cache hits, billing, provider model availability, or OS keychain persistence from mock tests. The ignored `assistant::tests::real_anthropic_once` test requires `AXDB_TEST_ANTHROPIC=1`, a key already in service `axdb` / account `ai:anthropic`, and explicit paid-call authorization.
